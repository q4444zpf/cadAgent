## 目标
模型超时、sidecar 崩溃、解析失败等核心故障有明确提示与本地日志；sidecar 可自动恢复；完成真实样图的端到端演示与验收清单。

## 涉及层
- [x] 数据层：本地日志文件
- [x] 逻辑层：日志、健康检查、自动重启、超时与取消

## 验收标准
- 结束 sidecar 进程后应用提示异常并自动恢复连接
- 日志能定位到失败环节（模型、sidecar、解析、校验）
- 用真实 DWG 转换样图完成“导入 → 问答高亮 → 参数确认 → 生成 → 校验 → 保存”演示
- 已知缺陷与限制写入交付说明

## 实现备注
- 日志：`src/node/logging/logger.ts` JSON 行日志写入用户数据目录 `logs/app.log`，512KB 轮转为 `app.log.1`，`readTail` 跳过损坏行；写入前对 `sk-` 密钥脱敏。已接入应用启动、sidecar 状态、图纸解析失败、模型问答/连接测试/参数整理失败、知识库导入失败。
- 诊断：`diagnostics:tail` / `diagnostics:open` IPC + 设置页「诊断日志」面板（路径、最近 300 行、刷新、打开文件夹）。
- 恢复：main 监听 sidecar 状态，异常时按 0.8s/1.6s/3.2s 退避自动重启（最多 3 次），每 20s 健康检查；恢复过程写入日志并实时更新界面状态。
- 测试：`tests/unit/logger.test.ts` 5 例（写入/尾部读取/轮转/脱敏/目录删除恢复）；`scripts/smoke-recovery.mjs` 通过测试专用 `sidecar:kill` IPC 终止进程，断言出现异常/恢复状态、恢复后 ezdxf 健康、日志包含「自动恢复成功」，并截图设置页日志面板。
- 交付说明见 `docs/交付说明.md`，包含环境、启动、测试命令与 8 项已知限制。
