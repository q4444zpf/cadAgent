# 重试、上限与文件生命周期

**Blocked by**: 020

## 目标
校验失败的问题清单回传模型，模型修改后重新保存，最多允许 3 次保存；仍失败则标记重试耗尽并保留文件与报告。生成状态通过事件驱动界面，超时与中止按既有约束处理文件与记录。

## 涉及层
- [ ] 数据层：`GenerationStatusEvent {listId, state, attempt, message?}`；`GenerationOutcome.exhausted`
- [ ] 逻辑层：`GenerationAgent` 统计保存次数，第 3 次保存后仍失败返回 `exhausted` 并中止；主进程广播状态 `preparing / drawing / saving / validating / retrying / done / failed`；180 秒总超时；中止时未落盘调用 `discard_dxf`、已落盘但未完成校验写记录 `issues: ["校验未完成：生成被中止"]`；单任务锁在任务结束（含失败）后释放
- [ ] UI层：生成按钮与结果区域展示状态机与重试进度；耗尽时明确提示未通过且文件已保留
- [ ] 测试：GenerationAgent 单测（问题反馈→修正→通过；第 3 次仍失败→`exhausted`）；主进程单测（状态事件顺序、锁释放、记录与文件生命周期）；smoke 通过 `SMOKE_GENERATE_FAIL` 驱动失败脚本 → 观察到 `retrying` 与耗尽提示，文件保留

## 验收标准
- 校验问题以工具结果返回模型，模型可再次调用绘图工具修改并保存
- 第 1、2 次保存后校验失败继续重试；第 3 次后仍失败停止并返回 `exhausted`，不再调用保存
- 状态事件按 `preparing → drawing → saving → validating →（retrying → saving → validating）→ done|failed` 顺序到达，界面不会重复启动生成
- 超时/中止且未落盘：无生成文件、无生成记录；已落盘未完成校验：保留文件并写入「校验未完成」记录
- 中止或失败后 `discard_dxf` 被调用，下一次生成可正常开始
- 生成过程不影响当前读图状态与任何原始图纸文件
