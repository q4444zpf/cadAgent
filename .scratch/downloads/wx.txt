【观点】｜阅读约 5 分钟
我认为，CAD 代码化正在成为必然趋势。不是因为某个演示很炫，而是因为设计和软件正在汇合。
特征树、约束、阵列这些「界面里的参数化」，本来就可以写成变量、循环和函数；大模型又恰好擅长读写代码。操作软件不会立刻消失，但设计意图的载体，正在从鼠标点击变成可执行、可对比、可交给智能体修改的文本。
2026 年 11 月 11 日，FaenoCAD 作者 Brian Ratliff 发了长文《Why Code-CAD.》。他用 Claude 写 build123d，配上记忆系统和轻量查看器。判断偏大胆，但方向我对得上。
一、特征树变成 main 函数，不是比喻，是同构
Brian 让 Claude 写 build123d，用记忆系统注入以往经验，再用轻量查看器把代码变量暴露出来：人改了哪个量，下一轮 Claude 会知道。提示是短段落加几张草图，分阶段结对往下做。
他把传统 CAD 概念一一对应到代码：
Constraints are just code variable reuse. Patterns are just for-loops.

特征树就是代码的 main 函数。钣金收成引用折弯、板厚和 K 因子的几何代码块。分析用的简化模型，在同一份源码里加开关即可。

图 1：约束、阵列、特征树和钣金，在代码里分别对应变量复用、循环、主流程和工艺参数。依据《Why Code-CAD.》整理，图为本号绘制。
我认同这个对应。复用尺寸、阵列孔、改一个参数带动一串特征，本来就是程序逻辑；界面把它藏进菜单，代码把它摊开。
模型是代码之后，Brian 主张用 git 代替传统 PLM：设计工程师建模，分析工程师开分支、加去特征开关，再提拉取请求。git 的 diff、分支和审阅，正好打在变体配置的痛点上。
我自己也在用 build123d 写参数化零件，也试过让智能体通过模型上下文协议（MCP）驱动 CAD。改系列尺寸和留下建模经验，代码比反复点特征树更稳。这不是说所有零件都该先写成脚本。
二、行业已经从三条线同时走向代码
如果这只是一个人的工作流，还谈不上趋势。开源代码 CAD、AI 原生的代码建模，以及主流 CAD 打开给脚本和智能体，其实是同时在发生。要让大模型参与建模，最顺的接口是代码，而不是去模拟鼠标。

build123d 和 CadQuery 都基于 Open Cascade，输出可做工程交换的边界表示（B-rep），而不是只看一眼的网格。OpenSCAD 没有官方 AI，但已经证明用文本定义几何可以走很多年。Zoo 的人和 AI 看同一份 KCL。text-to-cad 让智能体用 build123d 写 Python，本地预览并导出 STEP；发行包里也包括 MCP 组件。它火，不自动等于一次做对，但说明需求是真的。主流软件并没有站在对面：Onshape 的 FeatureScript 早就是官方自定义特征语言；西门子把 Designcenter 的 MCP 写进后续版本预告，发布后还要再核对实际开放范围。

代码不是开源圈子的爱好，而是 AI 进入 CAD 时最省事的表达。
三、趋势要落地，还要补上交付、审图和测量
说它是趋势，不等于明天关掉 NX 或 SolidWorks。关键是哪些环节已经适合用代码推进，哪些还要接回现有交付体系。
大装配、复杂曲面和消费电子的 A 级外观面，仍更常待在现有主力工具里。趋势会先占领规则清楚、参数明确的结构件，再向外扩展。
工厂和下游仍然大量要 STEP 和能指导加工的二维图。build123d 可以导出视图和 SVG / DXF，正式审签还得按企业模板补全公差、基准和几何尺寸与公差（GD&T）。
设计评审会多一层「读代码」；会签和供应商协同也不会因为改用 git 就自动齐备。更现实的做法，是先把 git 用在参数和配置上，再逐步接进现有 PLM。
2026 年 11 月 6 日提交的论文《Done Is Not Correct》让大模型根据文字规格用 build123d 写零件，再用内核测量尺寸、孔位和体积等是否落在公差带内。四个厂商的四种模型、每种架构 156 次尝试里，单次生成有 98% 宣称「做完了」，其中 14.1%（22/156）是能生成、能渲染，但至少一项语义检查没过的「静默失败」。如果强制智能体先测量几何再宣称完成，这一比例降到 3.2%（5/156），宣称完成时的正确率从 64% 升到 96%。任务只有 13 个，也没有装配，不能直接外推到整机项目。
能跑出来、能渲染，不等于做对了。 代码化的好处之一，就是可以把「测完再交付」写成工作流。
结构设计师现在就可以这样用：
1.标准件、系列件、支架、工装和规则清楚的钣金，先写成代码；改板厚、孔距时改参数更干净。
2.复杂造型、外观面、超大装配仍放在主力 CAD，再用 STEP 或接口对齐。
3.暂时不能换软件时，用官方或社区的 API / MCP 驱动现有 CAD，交付格式不变。
4.关键尺寸、孔位、壁厚、干涉都要量一遍，再进入审签。

图 3：规则清楚的结构件可以先代码化；造型与大装配仍接回主力 CAD；交付前用测量而不是只看「做完了」。图为本号绘制。
适合先走代码化的，是规则清楚、变体多的零件。 外观、超大装配和正式出图，是下一步要接上的环节，而不是否定方向的理由。
小结
●CAD 代码化是趋势：参数化本就是逻辑，三条线正在汇合。
●落地还要接上装配与曲面、图纸审签，以及「测完再宣称完成」。
●现在不必二选一：规则件用代码，复杂件和交付仍可留在主力 CAD。
