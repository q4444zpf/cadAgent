# CAD Agent 桌面软件 — 规格说明书

- 日期：2026-11-11
- 状态：已对齐（源自 grill-with-docs 访谈）
- 相关文档：`CONTEXT.md`、`docs/adr/0001~0003`

## 1. 问题陈述

水利/市政设计人员手头的工程图纸以 DWG 为主，图纸内容的查找、理解与复用依赖人工翻图；把设计需求变成规范图纸也依赖熟练制图人员。现有 CAD 软件不具备自然语言理解能力，通用聊天模型又无法可靠地读写图纸。

本项目要解决的是：让设计人员在桌面软件里**用自然语言读懂一张 CAD 图**，并**在规范/图集/历史图纸支撑下，经参数确认生成一张新的 CAD 图**。首版以可演示原型为目标，验证「Agent + CAD 工具 + 知识库」这条链路成立。

## 2. 方案概述

- **形态**：Electron 桌面应用（Windows），中文界面，左侧图纸预览、右侧对话。
- **运行时拆分**：
  - Node 主进程嵌入 `@earendil-works/pi-agent-core` 与 `pi-ai`，承载主 Agent、工具调度与会话。
  - Python sidecar（ezdxf）承载 DXF 解析、渲染数据、校验与绘图工具，通过本地 JSON 协议与 Node 通信。
- **读图**：解析图层、实体、文字、标注并展开块参照，保留实体句柄；Agent 回答引用实体，界面点击高亮。
- **知识库**：独立的**知识库智能体**子 Agent，检索本地知识库（规范文档、历史 DXF、参数表、扫描图）并返回带出处的结论；主 Agent 负责调用它。
- **生成**：主 Agent 整理参数清单与依据 → 用户**参数确认** → 调用语义化 CAD 工具生成 → 程序**校验** → 预览；校验失败反馈重试。
- **格式**：内部一律 DXF；DWG 经 ODA File Converter 转换后导入。
- **模型**：云端 API，Provider/模型/密钥可配置。

## 3. 用户故事

### A. 图纸导入与预览

- **US-1 导入 DXF**：用户选择 `.dxf` 文件后，应用显示预览与图层清单，并加载为当前图纸。
  - 验收：有效 DXF 能正确渲染主要实体；损坏或不支持的 DXF 给出可读错误，不崩溃。
- **US-2 DWG 引导**：用户选择 `.dwg` 文件时，应用明确提示需先转换为 DXF，并给出 ODA File Converter 的操作指引（若已配置转换器则提供一键转换）。
  - 验收：DWG 不会被静默当作 DXF 解析；提示与后续步骤清晰。
- **US-3 预览操作**：用户可缩放、平移、显示/隐藏图层。
  - 验收：图层开关实时生效；预览与图层清单一致。

### B. 读图问答

- **US-4 图纸结构化解析**：导入后，系统建立包含图层、实体类型、几何摘要、文字、标注与块展开结果的结构化索引，并为每个图元保留实体句柄。
  - 验收：对样图统计出的实体数量/图层清单与 ezdxf 直接解析一致；句柄稳定可复现。
- **US-5 自然语言问答**：用户就当前图纸提问，主 Agent 依据读图结果作答。
  - 验收：回答中的图层名、数量、尺寸等信息与图纸一致；无法确定时明确说明，不编造。
- **US-6 实体高亮定位**：回答中引用的实体句柄以可点击形式展示；点击后预览高亮对应图元。
  - 验收：单实体与多实体引用均可定位；高亮可取消。
- **US-7 回答带出处**：涉及规范/图集的结论必须引用知识库来源；涉及图纸的结论必须引用实体句柄。
  - 验收：每个专业结论至少有一条可追溯出处；无出处的推测被明确标注为推测。

### C. 知识库

- **US-8 知识库导入**：用户通过应用内管理面板导入 PDF、Word、DXF、PNG/JPG，并看到每个文件的解析/索引状态与失败原因。
  - 验收：四类文件均可成功入库；失败项显示原因并可重试。
- **US-9 混合检索**：知识库智能体对检索请求执行向量 + 关键词混合召回，返回片段、来源文件与位置（页码或实体句柄）。
  - 验收：基准问题能召回预期片段；返回结果必须携带来源信息。
- **US-10 扫描图识别**：扫描/图片图纸经视觉模型生成文字描述与结构化要点后入索引。
  - 验收：样图可被检索命中；识别结果标注来源为视觉识别，低置信内容不得作为唯一依据。
- **US-11 索引维护**：用户可删除文档、重建索引，并看到索引进度。
  - 验收：删除后不再被检索；重建后索引条数与文件内容一致。

### D. 生成新图

- **US-12 需求整理**：用户用自然语言描述生成需求，主 Agent 结合知识库输出参数清单（名称、值、单位、依据、待确认项）与必要假设。
  - 验收：参数清单覆盖所选图型的关键参数；每条参数有依据或明确标为假设。
- **US-13 参数确认**：界面展示参数清单，允许用户修改并确认；未确认前不得生成文件。
  - 验收：修改后的参数进入生成过程；用户取消则不产生任何 DXF。
- **US-14 生成与保存**：确认后，主 Agent 调用 CAD 工具生成图纸，另存为新的 DXF，并展示保存路径与预览。
  - 验收：生成的 DXF 可被 CAD 软件正常打开；预览与文件内容一致；不修改任何原始图纸。
- **US-15 生成校验与重试**：生成后自动回读校验（图层规范、实体完整性、标注完整性、关键几何闭合性）；失败时给出问题清单并允许自动重试（设上限）。
  - 验收：人为注入的错误能被规则捕获；重试后仍失败时明确终止并保留问题报告。
- **US-16 生成记录**：会话内保留每次生成的参数、校验结果与文件路径。
  - 验收：可回看历史生成记录并定位对应文件。

### E. 系统与配置

- **US-17 模型配置**：设置页可配置 Provider、模型与 API Key，并提供连接测试。
  - 验收：配置生效无需重启；密钥不明文落盘于项目目录。
- **US-18 会话管理**：支持新建会话、查看历史会话；会话关联当前图纸与知识库状态。
  - 验收：重启应用后可恢复历史会话的基本上下文。
- **US-19 故障可诊断**：模型超时、sidecar 崩溃、文件解析失败等核心故障有明确提示与本地日志。
  - 验收：日志能定位到失败环节；sidecar 崩溃后可恢复。

## 4. 已定决策

1. 能力边界：**读图问答 + 生成新图**；不修改原图（决策来源：访谈 Q1）。
2. 格式：DXF 原生；DWG 经 ODA File Converter 转 DXF（ADR-0001）。
3. 领域：水利/市政工程图；首批图型以真实 DWG 样图确定，当前**待定**。
4. 知识库内容：规范文档、历史 DXF、结构化参数表、扫描/图片图纸（含视觉识别）。
5. 知识库形态：**独立知识库子 Agent**；本地嵌入式向量库 + 关键词混合检索；回答必须带出处。
6. 生成方式：语义化 CAD 工具集 + 程序校验 + 失败重试（ADR-0003）；生成前必须参数确认。
7. 读图深度：图层、实体、文字、标注、块展开，保留实体句柄，支持界面高亮定位。
8. 产品形态：Windows 桌面应用，Electron 外壳，中文界面。
9. 运行时：嵌入式 Pi SDK（`pi-agent-core` + `pi-ai`）+ Python sidecar（ezdxf）（ADR-0002）。
10. 模型：云端 API，可配置。
11. 验收：程序化 DXF 规则校验 + 人工预览确认。
12. 交付目标：2–4 周可演示原型，不追求生产级安装与运维。
13. 首版一次只操作一张当前图纸；不做多图比对。

## 5. 测试决策

### 接缝

优先在这些稳定接口上测试，避免把测试绑死在 UI 或提示词细节上：

1. **CAD 服务协议（Node ↔ Python sidecar）**：`parse_dxf`、`render`、`validate_dxf`、绘图工具调用的 JSON 契约。
2. **Agent 工具接口**：读图、检索、绘图三大类工具的输入/输出契约（可用假模型驱动，不依赖真实 LLM）。
3. **知识库检索接口**：入库、混合检索、出处返回。
4. **桌面端到端**：导入 → 问答高亮；参数确认 → 生成 → 校验 → 保存。

### 各层测试

- **Python CAD 服务**：以固定样图 DXF 做单元/集成测试；断言图层、实体计数、句柄、校验规则命中；用 ezdxf 回读生成文件。
- **协议契约**：JSON Schema 校验；Node 侧 mock sidecar 测试错误分支。
- **知识库**：固定文档集与基准问题，断言召回片段与出处；删除/重建索引的一致性。
- **Agent 工具**：以脚本化假模型触发指定工具调用，验证工具参数与返回；真实模型效果用少量人工评测用例覆盖。
- **UI E2E**：Playwright 驱动 Electron，LLM 走录制响应或本地桩，覆盖两条主链路。
- **人工验收**：真实样图生成结果由人工在预览与 CAD 软件中确认。

### “完成”的定义

- 本规格全部用户故事验收项通过；
- 至少一张真实 DWG（转 DXF）样图完成「导入 → 问答高亮 → 生成 → 校验 → 保存」全链路演示；
- 生成的 DXF 在 AutoCAD 或等效软件中可正常打开且图面关键要素正确；
- 已知缺陷与限制写入交付说明。

## 6. 明确不做

- DWG 原生读写（仅经转换）。
- 修改既有图纸并回写。
- 扫描图自动矢量化或几何提取（仅作为知识来源做识别与检索）。
- 多用户、账号、权限、审计、云同步。
- AutoCAD 插件 / COM 自动化集成。
- 生产级安装包签名、自动更新、崩溃上报。
- 多语言界面（首版中文）。
- 移动端 / Web 部署。
- 制图规范的认证级合规保证。

## 7. 补充说明

### 前置条件

- 用户提供 2–3 张代表性 DWG，放入 `samples/`；安装 ODA File Converter 完成转换。
- 云端模型 API Key。
- 开发环境：Node.js（本机 v24）、uv 管理的 Python 环境；本机当前无 Rust 与系统 Python 路径，需按 ADR-0002 随应用打包。
- 首批图型确定后，再补充该图型的参数体系与工具清单（可能拆为独立 spec 或任务）。

### 风险

- **扫描图识别**是工期与准确率的主要风险，建议单独立项并设定置信度门槛。
- DWG→DXF 转换可能丢失专有特性，样图到手后需先做转换保真检查。
- 大图纸的全量结构化会消耗大量上下文，需要在读图层做分层摘要与按需展开。
- 云端模型意味着图纸内容出缡，演示阶段需使用非敏感样例。

### 性能期望（原型级）

- 典型样图（≤20 MB DXF）解析与索引在交互可接受时间内完成；
- 问答与生成延迟主要受模型服务影响，UI 必须提供进度与可取消状态。
