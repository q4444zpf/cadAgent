# CAD Agent 交付说明

## 1. 交付范围

本交付是基于 Pi Agent Harness 的 CAD 读图与生成桌面原型，覆盖：

- DXF 图纸导入、解析、预览、图层显隐
- DWG 自动转换为 DXF 后导入（依赖本机 ODA File Converter，转换结果按文件身份缓存）
- 大图纸摘要与按图层渐进加载（>50 MB）
- 自然语言读图问答（流式输出、工具调用可视化）
- 实体引用芯片与画布高亮
- 知识库导入（PDF / DOCX / DXF / CSV / 扫描图）、混合检索与出处展示
- 扫描图视觉识别与低置信提示
- 生成需求 → 参数清单整理 → 人工确认/取消
- 会话、消息、引用与生成记录的本地 SQLite 持久化，重启恢复
- 本地诊断日志、sidecar 健康检查与异常自动恢复
- 本地文件夹作为项目工作区：扫描文件与压缩包、按自然语言解压、按路径读取文件
- 对话框「选择文件」以附件上下文提问（只传路径与元数据，不复制文件）

## 2. 环境要求

| 组件 | 版本 / 说明 |
| --- | --- |
| 操作系统 | Windows 10/11（当前仅在此平台验证） |
| Node.js | 20 及以上，推荐 24 |
| Python | 3.12，使用 `uv` 管理依赖 |
| ODA File Converter | 可选，仅 DWG 自动转换需要；未安装时仍可导入 DXF |

Python 依赖：`ezdxf`、`pypdf`、`python-docx`。

## 3. 安装与启动

```bash
npm install
uv sync --project python
npm run dev
```

- 侧车启动时优先使用 `python/.venv`，不存在时回退到 `uv run --project python python -m cad_service`。
- 生产构建：`npm run build`，入口为 `out/main/index.js`。

## 4. 模型配置

进入「设置」页：

- 选择 Provider 与模型，填写 API Key 后保存。API Key 通过系统凭据库加密存储，不写入项目目录，也不会出现在日志中。
- 离线开发/测试可勾选「假模型模式」，问答、知识库子 Agent、参数整理均返回固定内容。
- 「测试连接」会发送一条测试消息验证配置。

## 5. 使用流程

1. 可选：在「图纸」页左侧「项目」面板点击「打开项目…」选择本地文件夹，该文件夹成为工作区根目录。项目打开后可让 Agent 扫描项目文件与压缩包、解压 ZIP/TAR/GZ、读取文本/PDF/DOCX 内容；也可点击对话框「选择文件」把项目内文件作为附件提问（附件只传路径与元数据，不复制文件）。
2. **图纸**页点击「打开图纸…」导入 DXF 或 DWG。DWG 会自动调用本机 ODA File Converter 转换为 DXF 后走同一套解析与渐进加载链路，界面显示「正在转换 DWG…」；转换结果缓存在用户数据目录 `dwg-cache/<sha1>.dxf`，同一文件再次打开直接命中缓存。未检测到转换器时返回「DWG 需先转换」，顶部提示条与设置页「DWG 转换器」给出下载、安装、重新检测指引，也可在自有 CAD 中另存为 DXF 后导入。
3. 在右侧「读图问答」提问，回答中的 `#句柄` 芯片可点击高亮对应实体。
4. **知识库**页导入资料后可直接检索；问答涉及规范时通过独立知识库子 Agent 检索并给出处。
5. **生成**页输入需求，点击「整理参数」；核对参数与假设标记后「确认参数」。
6. **历史**页查看会话消息、出处与生成记录，可打开或删除会话（删除不删除 DXF 文件）。重新打开会话时恢复项目工作区与附件芯片，文件已不存在时标记「已不存在」。
7. **设置**页底部「诊断日志」可查看最近日志并打开日志文件夹。

## 7. 已知限制与缺陷

1. **DWG 转换依赖外部程序**：DWG 自动转换依赖用户安装 ODA File Converter，未安装时仍会给出明确指引。实测 13 MB DWG 首次转换约 8 秒（输出 88 MB DXF），超时上限 300 秒；转换缓存按「路径 + 大小 + 修改时间」存放于用户数据目录 `dwg-cache/`，源文件更新后会生成新条目，旧缓存暂不自动清理。以 DWG 打开的会话在历史中记录的是缓存 DXF 路径，恢复时显示缓存文件名；清理缓存后需重新导入原 DWG。
2. **大图纸分级加载**：单张 DXF 超过 50 MB（如整套图纸的平面+纵断+横断合集）时先返回摘要：统计图层、实体类型、包围盒与文字样例；随后按图层实体数从小到大异步取几何并渐进渲染，最小图层先出现，重图层最后加载。加载过程中可继续缩放、平移，完成后图层显隐可用。摘要结果按「路径 + 大小 + 修改时间」落盘缓存，再次打开可秒开；命中缓存时首个图层请求仍需解析整张图纸。实测 85 MB 测量图：摘要约 27–49 秒，23 个非空图层、238,867 个图元，DMTZ 12,603 实体约 0.4 秒、GCD 25,741 实体约 2 秒、最大 ZBTZ 74,947 个插入（展开 169,978 个图元）约 5 秒，全部图层约 16 秒加载完成。读图问答仍基于摘要，按实体检索/高亮暂不可用。
3. **首批图型待确认**：`samples/` 已有 3 份真实 DWG 样例，但首批图型与参数体系尚未最终确认（ticket 010 未完成）。
4. **生成与校验未实现**：参数确认后仅保留数值供后续生成使用，当前不会写出任何 DXF；首图型生成（011）与校验重试（012）依赖真实样例，尚未落地。
5. **生成记录为空**：历史页的生成记录数据结构、IPC 与界面已就绪，但尚无生成流程写入记录。
6. **扫描图识别依赖云端模型**：识别结果可能低置信（示例置信度 0.55），界面会标记「低置信」并提示人工核对。
7. **知识库检索为演示级实现**：使用哈希向量与关键词混合打分，不等同于生产级语义检索。
8. **未做安装包与自动更新**：交付形态为源码 + 本地构建，未提供 Windows 安装程序。
9. **平台覆盖有限**：仅在 Windows 上完成自动化验证，macOS/Linux 未验证。
10. **项目工作区与附件限制**：压缩包仅支持 ZIP/TAR/GZ（不支持 RAR/7z）；解压默认落到包旁新目录、不覆盖，重名自动加序号，所有读写路径限制在项目根目录内（拒绝绝对路径、盘符、UNC 与 `..` 越界，防 zip-slip）；单次解压上限 10,000 条目 / 2 GiB，扫描单次最多枚举 5,000 条目，读取文件上限 20 MiB（文本默认 20,000 字，PDF 最多 50 页，DOCX 最多 500 段）。附件只传路径与元数据、不复制文件，源文件被移动或删除后历史会话中标记「已不存在」，提问仍可使用其余内容。

## 8. 故障排查

- 状态徽标显示「侧车服务异常」时，先查看设置页「诊断日志」；sidecar 会自动尝试最多 3 次恢复（退避 0.8s / 1.6s / 3.2s）。
- 日志按 `scope` 区分失败环节：`model`（模型调用）、`sidecar`（侧车）、`parse`（图纸解析）、`convert`（DWG 转换）、`kb`（知识库）。
- 日志文件位于用户数据目录 `logs/app.log`，超过 512KB 自动轮转为 `app.log.1`。
- 日志写入前会对疑似 `sk-` 密钥进行脱敏。
